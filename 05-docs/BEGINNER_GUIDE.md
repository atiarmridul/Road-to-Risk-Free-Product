# Beginner Guide

> **সহজভাবে / In simple words:** You do not need programming experience to begin learning software quality.

## What is software testing?

Imagine that a school creates an online result system. Before students use it, someone should check questions such as:

- Can a student sign in with the correct password?
- What happens with a wrong password?
- Does each student see only their own result?
- Is the total calculated correctly?
- Does it work on a phone and a computer?
- What happens when the internet is slow?

Asking these questions, trying the situations, and explaining problems clearly are parts of software testing.

## A simple way to answer questions

Use this four-part structure:

1. **Meaning:** Explain the idea in simple words.
2. **Example:** Give a familiar situation.
3. **Risk:** Explain what could go wrong.
4. **Check:** Explain how you would test it.

Example:

> Boundary-value testing checks values near a rule’s limits. If a school club accepts students aged 12 through 16, I would test 11, 12, 16, and 17 because mistakes often happen at the edges.

## Healthy learning rules

- It is normal not to understand everything on the first reading.
- Do not memorize a tool command before understanding its purpose.
- “I do not know yet, but this is how I would investigate” is better than inventing an answer.
- Testing is not about blaming developers; it is about helping the team understand product risk.
- A test is valuable when it provides useful information, not because it makes a large test-case count.
