# Beginner QA Glossary

> **সহজভাবে / In simple words:** This glossary translates common QA and software words into short, everyday explanations.

| Term | Plain-language meaning |
| --- | --- |
| Acceptance criteria | Rules that describe when a feature is considered complete and correct |
| API | A defined way for two software systems to communicate |
| Assertion | A check that compares the actual result with the expected result |
| Authentication | Proving who you are, such as by signing in |
| Authorization | Checking what an identified person is allowed to do |
| Automation | Using code or tools to repeat work automatically |
| Boundary value | A value at or just beside the edge of an allowed range |
| Bug or defect | A problem where software behaves incorrectly or creates unacceptable risk |
| Build | A packaged version of software that can be tested or released |
| Cache | A temporary copy of data kept to make future access faster |
| CI/CD | An automated process for building, checking, and delivering software changes |
| Client | The app, browser, or system that sends a request |
| Contract test | A check that two services agree on exchanged data |
| Database | An organized place where software stores information |
| Endpoint | A specific API address used for an operation |
| Environment | A configured place where software runs, such as test or production |
| Exploratory testing | Learning and testing at the same time instead of following only fixed steps |
| Flaky test | A test that sometimes passes and sometimes fails without a meaningful product change |
| Framework | A reusable structure and set of rules for building tests or software |
| HTTP | A standard used to exchange web requests and responses |
| Idempotency | Repeating the same operation does not create an unintended additional result |
| Integration | A connection between separate components or systems |
| Latency | Time spent waiting before a response begins or a request reaches a stage |
| Load testing | Checking behavior when many users or requests use the system |
| Log | A time-ordered record of events produced by software |
| Metric | A measured value used to understand behavior or trends |
| Mock | A controlled replacement for a real dependency during a test |
| Negative testing | Checking invalid, missing, forbidden, or unexpected input and behavior |
| Percentile | A value showing how most results performed, such as the speed experienced by 95% of requests |
| Production | The live system used by real customers |
| Regression testing | Checking that existing behavior still works after a change |
| Reliability | The ability to keep providing the expected service over time |
| Request | A message asking a system to perform an action or return information |
| Response | The result a system sends back after a request |
| Risk | The combination of how likely a problem is and how harmful it would be |
| Sanity testing | A focused check that a particular change works well enough for deeper testing |
| Schema | A definition of how data is structured |
| Severity | How seriously a defect affects the product or users |
| Smoke testing | A short check that the most important functions work at a basic level |
| Sprint | A short, fixed period in which an Agile team completes planned work |
| Status code | A number summarizing the outcome of an HTTP request |
| Stub | A simple replacement that returns prepared data during a test |
| Test case | Preconditions, actions, data, and expected results for checking behavior |
| Test data | Information prepared or selected for testing |
| Test environment | Hardware, software, services, accounts, and settings used for testing |
| Test scenario | A high-level situation or user goal that should be checked |
| Throughput | The amount of work completed during a period of time |
| Trace | A connected record showing how one request travelled through services |
| Unit test | A test of one small piece of code in isolation |
| User story | A short description of a need from a user’s perspective |
| Validation | Checking whether the product solves the intended user need |
| Verification | Checking whether work follows its specification or design |

When a note contains an unfamiliar word that is not listed here, add it to this glossary with a one-sentence explanation.
