> A bilingual (Bangla and English) QA engineering knowledge base for practical learning and interview preparation.

## How to use the notes

Use a short evidence-based loop instead of reading every file in order:

1. **Understand:** Read one topic and summarize it in your own words.
2. **Apply:** Create a small example, checklist, test case, query, or script.
3. **Explain:** Give a two-minute spoken explanation covering purpose, example, risk, and trade-off.
4. **Check:** Answer the note's review questions without looking back.
5. **Record:** Mark what is clear, what needs practice, and the next topic.

Treat PDFs as supplementary sources. The Markdown notes are the maintained learning and navigation layer.

## Content conventions

- Keep one primary topic per Markdown file.
- Use lowercase kebab-case for new file and directory names.
- Add new content to the nearest section README.
- Prefer practical examples, trade-offs, and measurable outcomes over definitions alone.
- Do not commit credentials, local environment files, logs, or generated test reports.

## Maintenance

This is a living study repository. Some notes are personal and bilingual by design. Before sharing the repository publicly, review personal details in interview answers and ensure every claimed tool or result reflects current experience.
