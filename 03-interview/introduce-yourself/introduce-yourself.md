### **What is Cross-Origin Resource Sharing (CORS)?**

Cross-origin resource sharing (CORS) is a mechanism for integrating applications. CORS defines a way for client web applications that are loaded in one domain to interact with resources in a different domain. This is useful because complex applications often reference third-party APIs and resources in their client-side code. For example, your application may use your browser to pull videos from a video platform API, use fonts from a public font library, or display weather data from a national weather database. CORS allows the client browser to check with the third-party servers if the request is authorized before any data transfers.

**CORS errors happen when a webpage makes a request to a different domain than the one that served the page, and the server responds with an HTTP error because the “Origin” header in the request is not allowed by the server's CORS configuration**

### As a mid-senior level Software Quality Assurance (SQA) engineer, your day-to-day activities would typically involve a combination of strategic, technical, and collaborative tasks. Here's an outline of common responsibilities:

### 1. **Test Planning and Strategy**

- **Test Strategy Development**: Participate in designing the test strategy and determining the scope of testing for new features or releases.

- **Requirement Analysis**: Review and analyze requirements to ensure they are clear, testable, and complete.

- **Test Estimation**: Provide time estimates for testing activities and contribute to project timelines.

### 2. **Test Case Design and Management**

- **Test Case Design**: Write detailed test cases (manual or automated) based on functional and non-functional requirements.

- **Test Data Management**: Create and maintain test data sets for various test cases.

- **Review**: Review test cases written by junior team members and provide constructive feedback.

- **Test Case Repository**: Manage and maintain a well-organized repository of test cases.

### 3. **Automation and Tooling**

- **Test Automation**: Design, develop, and maintain automated test scripts, likely using tools like Playwright, Selenium, or other frameworks.

- **CI/CD Integration**: Work with DevOps teams to integrate automated tests into the CI/CD pipeline for continuous testing.

- **Tool Evaluation**: Evaluate and implement new testing tools or frameworks to improve testing efficiency.

### 4. **Test Execution**

- **Manual Testing**: Execute manual test cases for new features, regression, and smoke testing.

- **Automated Test Execution**: Run automated tests and monitor results in CI/CD pipelines.

- **Cross-Browser and Platform Testing**: Ensure software functions across different browsers, devices, and platforms.

- **API Testing**: Execute API testing using tools like Postman or custom automation scripts.

### 5. **Bug Tracking and Reporting**

- **Defect Reporting**: Identify, log, and track defects in the bug tracking system (e.g., JIRA, Bugzilla).

- **Defect Verification**: Retest defect fixes and ensure resolution before release.

- **Metrics and Reporting**: Provide testing progress reports, defect status reports, and key metrics to stakeholders.

### 6. **Collaboration and Communication**

- **Scrum Participation**: Attend daily stand-ups, sprint planning, and retrospectives. Collaborate closely with developers, business analysts, and product owners.

- **Code Reviews**: Participate in code reviews, especially for automated test scripts.

- **Stakeholder Communication**: Regularly communicate test results, risks, and project status with stakeholders.

### 7. **Mentorship and Leadership**

- **Mentor Junior Testers**: Provide guidance and mentorship to junior SQA engineers, including reviewing their work and helping them grow.

- **Process Improvement**: Identify areas for process improvement and help implement more efficient workflows.

### 8. **Regression and Release Testing**

- **Regression Testing**: Run comprehensive regression tests to ensure new changes haven’t broken existing functionality.

- **Release Testing**: Conduct final testing of the application before release, ensuring the product is stable and meets quality standards.

### 9. **Exploratory Testing**

- **Ad-hoc Testing**: Perform exploratory and ad-hoc testing to uncover edge cases or defects that might not be covered by scripted tests.

### 10. **Non-Functional Testing**

- **Performance Testing**: Involved in performance, load, and stress testing activities.

- **Security Testing**: Collaborate with security teams to ensure the software is free from vulnerabilities.

### Tools commonly used:

- **Test Automation**: Playwright, WebdriverIO, Selenium

- **CI/CD**: GitHub Actions

- **Bug Tracking**: JIRA

- **Version Control**: Git, GitHub

- **API Testing**: Postman

- Performance Testing: JMeter
