# QA Interview Readiness Checklist

> **সহজভাবে / In simple words:** Interview preparation means connecting technical knowledge to honest examples from your own experience.
>
> **কেন গুরুত্বপূর্ণ / Why it matters:** A checklist helps you find weak areas before the interview instead of memorizing random answers.


Mark an item complete only when you can explain it aloud without reading and handle at least one follow-up question.

## Personal narrative

- [ ] Deliver a 60–90 second introduction tailored to the role.
- [ ] Explain two recent projects: product, users, architecture, responsibilities, and risks.
- [ ] Prepare three achievements with honest, measurable outcomes.
- [ ] Prepare one mistake or failure and explain what changed afterward.
- [ ] Explain a conflict, a leadership example, and how you mentored someone.
- [ ] Confirm every technology mentioned on the résumé can be defended with an example.

## Core QA knowledge

- [ ] Explain verification vs. validation and severity vs. priority.
- [ ] Compare smoke, sanity, regression, retesting, exploratory, and UAT.
- [ ] Apply equivalence partitioning, boundary values, decision tables, and state transitions.
- [ ] Describe a defect lifecycle and write a high-quality defect report.
- [ ] Build a risk-based test plan when time is limited.
- [ ] Define entry criteria, exit criteria, coverage, and release recommendation.

## Technical depth

- [ ] Design positive, negative, authorization, validation, and idempotency API tests.
- [ ] Explain common HTTP methods and status codes with examples.
- [ ] Validate API data against a database using practical SQL queries.
- [ ] Explain the test pyramid and where UI, API, integration, and unit tests belong.
- [ ] Describe selectors, waits, assertions, page objects, retries, and flaky-test diagnosis.
- [ ] Explain what should and should not be automated using risk and return on investment.
- [ ] Interpret response time percentiles, throughput, error rate, and JMeter results.
- [ ] Cover authentication, authorization, injection, sessions, sensitive data, and OWASP risks.
- [ ] Test a critical workflow using keyboard, zoom, automated accessibility checks, and a screen reader.
- [ ] Explain which tests belong at each CI/CD stage and how quality gates are governed.
- [ ] Connect logs, metrics, traces, and business signals to release validation and incident investigation.

## Senior-level scenarios

- [ ] Handle a critical production defect from containment through prevention.
- [ ] Make and communicate a release go/no-go recommendation.
- [ ] Prioritize regression under a compressed timeline.
- [ ] Explain quality metrics without relying only on test-case counts or pass rate.
- [ ] Address unclear requirements, unstable environments, and cross-team dependencies.
- [ ] Explain how to introduce or improve CI/CD quality gates.

## Final 24 hours

- [ ] Re-read the job description and map each requirement to one example.
- [ ] Verify résumé dates, role details, company name, and interviewer information.
- [ ] Test the meeting link, microphone, camera, screen sharing, and internet backup.
- [ ] Prepare a notebook, water, résumé copy, and project highlights.
- [ ] Prepare three questions for the interviewer.
- [ ] Stop heavy study early enough to rest.

## Questions to ask the interviewer

- What quality risks are most important for this team today?
- How are release decisions made, and what role does QA play in them?
- What does success in the first 90 days look like for this role?
- How is automation divided across unit, API, integration, UI, and mobile layers?
- What is the team’s approach to production monitoring and escaped defects?
