# Test-Driven Development Learning Guide

Test-driven development means writing a small failing test before writing the production code that makes it pass.

## Recommended learning order

1. [Foundations](foundations.md) — Red, Green, Refactor and the basic cycle
2. [PHP walkthrough](php-walkthrough.md) — build behavior one test at a time
3. [JavaScript walkthrough](javascript-walkthrough.md) — repeat the cycle with Jest
4. [Advanced design](advanced-design.md) — TDD laws, styles, patterns, legacy code, and BDD
5. [Acceptance, API, and katas](acceptance-api-and-katas.md) — ATDD, API-first work, limits, and exercises
6. [Bangladesh example](bangladesh-example.md) — a locally familiar validation problem
7. [Review](best-practices-and-review.md) — benefits, challenges, mistakes, and summary

## Beginner mental model

Red means the new test fails, Green means the smallest solution passes, and Refactor means improve the code without changing behavior.
