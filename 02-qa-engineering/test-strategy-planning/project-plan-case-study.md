# Project Plan Review - QA Case Study

> **সহজভাবে / In simple words:** A project plan explains the work, people, timing, dependencies, and risks of a project.
>
> **কেন গুরুত্বপূর্ণ / Why it matters:** QA reviews the plan early so testing, environments, data, and release activities are not forgotten.


The CST+ project-plan resource is retained as a planning case study rather than merged into general testing definitions.

## QA review questions for a project plan

- Are scope, assumptions, dependencies, and exclusions explicit?
- Are acceptance criteria and quality attributes measurable?
- Does the schedule include requirement review, environment readiness, test cycles, defect correction, regression, and release validation?
- Are roles and escalation paths clear across product, engineering, QA, operations, and external parties?
- Are test data, integrations, migrations, devices, and non-functional risks planned?
- Do milestones have evidence-based entry and exit criteria?
- Is there a communication, incident, rollback, and post-release monitoring plan?
- Are high-risk dependencies assigned owners and contingency actions?

## Interview application

When asked how QA joins a new project, explain how you review the project plan, architecture, user journeys, dependencies, risks, environments, data, delivery milestones, and definitions of ready and done before building the test strategy.
