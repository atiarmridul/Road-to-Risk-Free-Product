# Advanced QA Engineering

This section moves beyond individual test cases into product risk, delivery systems, release decisions, and continuous improvement. Start here after you are comfortable with testing foundations and at least one practical area such as API, database, or UI testing.

## Recommended learning order

| Stage | Topic | Main question |
| ---: | --- | --- |
| 1 | [Test strategy and planning](test-strategy-planning/test-strategy-planning.md) | How should testing respond to product risk and constraints? |
| 2 | [Test data and environment management](test-data-environment-management/test-data-environment-management.md) | How do we make test evidence reliable and repeatable? |
| 3 | [CI/CD quality strategy](ci-cd-quality-strategy/ci-cd-quality-strategy.md) | Which checks should run where in the delivery pipeline? |
| 4 | [Quality gates and release readiness](quality-gate-release-readiness/quality-gate-release-readiness.md) | What evidence supports a release decision? |
| 5 | [Defect management and quality metrics](defect-management-quality-metrics/defect-management-quality-metrics.md) | Which signals help the team improve instead of merely count activity? |
| 6 | [Production observability](production-observability/production-observability.md) | How do production signals complete the quality feedback loop? |

## Completion checkpoint

Choose a familiar product and create a one-page quality approach containing its top risks, test layers, data and environment needs, release evidence, production signals, and two useful metrics. You understand this section when you can defend those choices and their trade-offs.
